## 〇、核心认知（完整版）

**图有两个层面，重心永远在画面层（2026-09-10 阁下纠正）。**
- **画面层**——内容/场景/这张图要干什么：**每次都要答**，这是核心要点。
- **文件层**——EXIF/块结构/尾拼/像素 LSB：**附加参考**，图有蹊跷时才动（来源不明、画面明显缺一块、上下文暗示有货、对方语气带钩子、**对方问的是形态而不是内容**——「这图会不会动／有没有声音」这类问题只有字节答得出）。

❌ 反例：把「收到图先 probe」做成条件反射——阁下随手发张日常照，上去就查隐写，很尴尬。✅ 正例：先看画面答「这是什么」，文件层当备用口袋。工具与流程 → `credential-management/references/steganography.md`（实战经验第一条）。

**视觉模型的输出是「它认为的」，不是「图上事实」。** 最坑的方向：文字、颜色、身份、**数量与视角**——全部实测翻车过（单侧蝴蝶结读成「左右各一」、俯视读成仰视、背景的连拱建筑读成「拱桥」）。

**判定「两张图是不是同一张」，vision 描述不能当证据——只认硬字段：像素尺寸、时间戳、md5/dhash。** 描述只用来比对「有没有明显不同的元素」。

**要看两个版本「差在哪一块」（有水印/无水印、改没改过），走像素差分定位**——归一化尺寸 → 逐像素差分 → 高斯模糊压掉错位噪声 → 连通域热点表，再裁热点放大读字。配方、判读表与脚本（`scripts/imgdiff.py`）→ `image-diff-forensics.md`。差分只说「哪一块不一样」；那块是不是水印，还要**裁开放大看画面** + **翻文件层看声明**两头对。同一张图两轮读法打架是常态；更麻烦的是旧记录里的尺寸/时间字段本身可能被模板抄错，即使同一份 md 内部也会互相矛盾——**字段之间打架就停下来要原档，别挑一条顺眼的信**。

**找回原档的实搋（你说「这张图应该存过」时）：dhash（8×8）扫本地图库，别用 md5 单比。** 转发/导出/上传会重编码——字节数变了、尺寸不变、**dhash 距离 ≤8 就是同一张**（实测：同一张图原档 4,897,064 B 与 QQ 副本 5,237,032 B，距离 5）；距离 20+ 才是不同图（同库不同图最近也常在 20 上下）。扫 `workspace/`、`repos/`、`archive/` 三棵树；命中后**存原档**，不存传输副本（副本体量、体积都不可靠）。顺手记住一个惯例：阁下投喂的成品原图文件名常是 **13 位毫秒时间戳**，直接换算就是生成时刻。

**识图的第一任务是「这是什么」，不是「有没有毛病」（2026-09-10 阁下纠正：「我是觉得你的问法有问题，应该考虑的是，这张图是什么」）。** 本天使当时盯着「检查有没有瑕疵」，把「认出来是什么」整个漏了——本末倒置，而且会把诱导出来的假瑕疵当结论。**先客观描述、先认出对象**；瑕疵只作为描述的一部分，且必须另用中性问法复核才算数。标准问法模板 → `../templates/objective-describe.md`。

## 通用对策

0. **验证配得上证据强度——别为验而验**：结构/线条类元素（连线几何、箭头有无、布局排位）整图识别一次就稳——两家模型读法一致即可定论，**不需要裁切逐段复核**。裁切放大终审是文字类小字/水印/生僻字的专属手段（陷阱 1/7），别套到线条结构上。复核触发条件：出现冲突证据才裁切。
1. **自家有档案先查档案**（角色/作品资料库），别让模型裸猜——但查档是为了**核验与补细节**，不是认图的必经步骤：画面指纹（姿势/道具/背景/镜头视角）能直接指认的对象，先报指认结果再查档；把「认出这是什么」做成「通读一遍资料库」是绕远路
2. **模型点名当线索不当结论**，拿不准标「疑似」不建档/不定论
3. **关键信息（文字/角色/出处）找人多源验证**——B站搜索页、搜狗微信、百科，别搜一次就放弃
4. **密集数字表漏格是常态**——空值标 `—` 绝不脑补填数，用文字报道交叉印证
5. **格式/环境坑**：
   - **`vision_analyze region` 越界不报错，而是静默产出垃圾**——region 是**原图像素坐标**，当 x2/y2 超出原图宽高时裁切会补边，模型于是答「左侧被裁掉了，只看到某一个图标」（把补边当成图本身缺失）。**裁之前先用 PIL 确认原图尺寸**（`python3 -c "from PIL import Image; print(Image.open(p).size)"`），坐标一律落在尺寸内；小图标条本就该先裁剪放大再问，而不是拿整图硬问
   - **mmx vision 不支持 gif**——gif 先 PIL `Image.open(path).convert('RGB')` 存 png 再识别
   - **后台进程不继承 PATH/venv**——脚本内显式用绝对路径 `/opt/data/.npm-global/bin/mmx` 和 `/opt/data/.venv/bin/python3`
   - **批量识别必须断点续传**——每张图识别完立即 json.dump 写盘，失败不中断
   - **装饰分隔图去重**——正文插图常含重复分隔图，按文件名去重只识别一次
   - **card/ 前缀图片在子目录**——完整性检查时要去子目录找
6. **多模型交叉验证** — 同一张图 + 同一个提示词喂 2+ 个模型，结果分别建档再对比。判别规则：
   - **同模型换问法自检（2026-09-10 实战；单眼链路唯一自检手段）**：判断一个「瑕疵/异常」结论可不可信，同一张图跑三种问法对照——① 诱导式（「检查有没有瑕疵」）② 半诱导（「手指有没有粘连/穿模？」，选项里塞瑕疵词）③ 纯中性（「描述手的位置和动作」，全文不出现任何问题词）。结论只在①②出现 = **问出来的，丢弃**；③ 仍稳定出现 = 站得住。此法不消耗第二个模型，也不受「同模型两票不算两票」限制
   - 多数派优先，独票存疑
   - **粤语/方言字是陷阱 1 重灾区，三条判据（2026-09-10 实战）**：粤语用字（瞓/睇/咗/喺/嗰/畀/咩/㗎）**同一模型整图与放大读数会互斥**（mmx 整图读「瞓」→ 放大读「睇」）。① **语义优先**——「你瞓到成只猪咁」（睡得像猪，呼应下句「我饿到见到咩都想食埋佢」）成立，「睇到成只猪咁」在粤语里不成话；② 多数派（ds-vision 读「睇」，mmx + DeepSeek 读「瞓」）；③ **模型的英文翻译可作自洽性检验**——ds-vision 读「睇」却翻成 "you look like a whole pig"，语义自曝读错
   - **小字放大有上限，别死磕（同日实战）**：18-28px 正文小字 LANCZOS 放到 6-8 倍后，三家模型（ds-vision/mmx/deepseek-flash）**集体幻觉**——「你瞓到成只猪咁」被读成「出眠到啦。你睡到成只猪啦」，甚至补出图上不存在的整句；**裁得越紧越编**。放大上限 **3-4 倍**且必须带整行上下文，别单字裁；放大读数与原图读数冲突时 **原图 + 语义优先**；再定不了就按铁律问人，别耗轮次
   - **手写体/装饰体/被压住的文字：宁缺勿圆（2026-09-11）**——这类字体的多轮读数冲突是常态（同一张图三版给三个答案）；**语境补全（生日清单→cake/gift/card）是幻觉入口，不是推理**。落档姿势：可见字母照录 + `[遮挡]` 标注 + 「以原图为准」，存疑项进档案时明写存疑，别让后手把识别结果当事实用
   - 数量类元素：**漏报是常态，独报多/独报少都要复核**（裁切复核终审）
   - **悬浮物/手持物读法最不稳定**——以最具体的客观描述为准；**手势/手指数同样不可靠**：竖的是哪根手指、比的是几根，同一张图换设置能读出跟人对不上的答案——这类细节以人（阁下原话）为准，不拿模型读数去顶
   - 模型会脑补设定名——抓到就记进该模型黑账
   - **分歧点用裁切复核终审**（PIL 裁剪争议区域放大 2 倍再识图）
   - **宽幅多栏截图按列裁剪放大再识图**（游戏圈/社交截图常是左中右多栏拼图）
   - **超长竖截图按高度分段识别**（1280×23020 分 4-6 段，prompt「把图上所有条目文字完整读出来」）
   - **中等竖图（3-4k px）分 3 段 ×2 倍 LANCZOS 即可完整读表**（800×3500 官方 Q&A 长图）
   - **聊天/私信长截图（4-7k px）分 4 段 + mmx 乱序坑**——⚠️ **mmx 分段识别会从下往上读消息，段内乱序**，归档前必须**按时间戳重排**；prompt 显式要求「气泡方向+时间戳」；系统提示/自动回复单独标注，别当真人对话
   - **聊天截图要原话归档 → 优先 ds-vision + 逐字 prompt（2026-09-10 实战）**：mmx 对聊天截图给的是**英文转述+猜测**（"appears to be…" "likely…"），逐字入库会失真；ds-vision 分段跑固定 prompt 能直接拿到中文原话。流程：PIL 竖图切 2~3 段（1920 高 → 每段约 600px）× 2 倍 LANCZOS → 逐段 `bin/ds-vision <段图> "把图上所有文字从上到下原样读出来：日期分隔行、时间戳、昵称、每条消息全文。不要翻译、不要总结、不要脑补，读不出的字标[?]"`——一次拿到 `03/12 01:47` 这类时间戳 + 逐条原话，可直接进档案。想双保险就先 mmx 定位内容、再 ds-vision 出原话。**聊天截图只给「月/日 + 时:分」（如 `03/12 01:47`），没有年份——年份靠消息内容推 + 与上下文事件对齐**（实例：「我挺希望今年30周年」→ 2026），别默认当年，也别在档案里把月/日当完整日期
7. **mmx 输出语言不固定**：批量识图归档时先扫输出语言，英文总结要转回中文再入库；输出语言≠图内语言
8. **题目/问答类截图先定位题面，别陷进出处考据**（2026-08-28 实战）：收到游戏截图+「解这道题」类请求，第一轮就该问「底部/顶部提示文字是什么」——题面自己会说话（本例底部直接写着「观察图中每种生物的生命周期…」，答案就藏在图中关系里）。别先追「这是哪个游戏的哪个活动」——模型归属不可靠（陷阱10）、搜索也会跟着跑偏（搜「仿生摹行」搜出一堆无关视频），白花轮次还容易被阁下纠正「想复杂了」。
