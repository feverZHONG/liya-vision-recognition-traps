# 两图差分定位 —— 「这两张有什么不一样」

> 触发：用户甩来两个版本（原图/无水印版/转发版/改过的图）问「看出区别了吗」「哪张有水印」「哪张是原图」。
> 画面层的「这是什么」照常用视觉模型；**差在哪一块是文件层事实，靠像素差分定位**——肉眼不可靠，视觉模型的「两图不同」也不是证据。
> **先认物件，再谈差分（2026-09-15 纠正）**：报完「哪张有水印」还要答出**这拍的是什么**——只盯着文件层，能说出水印在第几字节，却认不出这是哪本书/哪个东西，等于没答。认物件优先查本地档案（购物簿/作品库/外源档）：够得着的东西，用户多半登过记。
> **顺手对一眼眼前这张跟库里那张是不是同一张画面**（商品宣传图/开箱抽帧/官方图）：对不上就先当疑点问一句，别默默放过。

## 一、先看硬字段（能省掉整轮回话）

| 看什么 | 怎么拿 | 读出来什么 |
|---|---|---|
| 尺寸 | `Image.open(p).size` | 差 1px 级别 = 同一份画面的两套存档/两条导出管线，不是两次按快门 |
| EXIF `DateTime` + `Make`/`Model` | `im.getexif()` | 同秒同机型 = 同一次拍摄（或同秒连拍） |
| 容器格式 | `im.format`（`JPEG` / `MPO`） | MPO = 多帧容器（第二帧常是 HDR 增益图）；两版容器不同 = 走了两条保存管线 |
| md5 | `md5sum` 两个文件 | 相同即同一文件，后面一步都不用做 |

## 二、差分配方（定位差异落在哪一小块）

现成脚本：`scripts/imgdiff.py A.jpg B.jpg` —— 出尺寸/EXIF/热点块表/连通域清单，不改文件。手写时按这套：

```python
from PIL import Image, ImageFilter
import numpy as np
from scipy import ndimage

a = Image.open(p1).convert('RGB')
b = Image.open(p2).convert('RGB').resize(a.size, Image.LANCZOS)   # 必须先归一化尺寸
na, nb = np.asarray(a).astype(np.int16), np.asarray(b).astype(np.int16)
d = np.abs(na - nb).sum(axis=2)                                   # 每像素 0~765
dblur = np.asarray(Image.fromarray(np.clip(d, 0, 255).astype('uint8'))
                   .filter(ImageFilter.GaussianBlur(6))).astype(float)

# ① 热点表：64 或 256 px 一块，块内均值排序看前几块
# ② 连通域：ndimage.label(dblur > 25)，按面积排序，看每个 blob 的 bbox 与 maxdiff
```

- **必须先 resize 到同一尺寸**：两图差 1px 时直接相减，整张图全是假边缘，热点表没意义
- **先 GaussianBlur 再找热点**：1px 级错位 + JPEG 量化噪声会淹没真正的水印块
- 出热点表 → 裁该区域做上下拼图（上=图A / 下=图B，中间垫色条）→ **这时候才让视觉模型上场，只负责读那几行字**

## 三、判读表（差异是什么性质）

| 差分形态 | 是什么 | 能当「有水印/改过图」吗 |
|---|---|---|
| 锐边连通块、宽:高 ≈ 一行字的比例、水平排开成串 | 文字水印/叠加物（时间戳、平台号、署名） | ✅ 就是它 |
| 弥散亮带、无定形云块、里面没有笔画结构 | 光照/色调映射差异（两版走不同 HDR/增益图渲染路径） | ❌ 不是内容差 |
| 全图均匀低值噪声 | 重编码/量化差异（换了容器、压过一遍） | ❌ |
| 沿所有文字与边缘均匀分布 | 两次独立曝光，或一方被锐化过 | ❌ |
| 大块补丁状、边缘发虚 | 涂抹修补（去水印、消除笔） | ✅ 但要裁开放大看接缝 |

## 四、收尾：报给用户什么

1. **哪张有、哪张没有**——用可辨识的特征指代（体积/尺寸/文件名），别只说「有一张」
2. **位置 + 逐字读数**：裁该块放大 2~3 倍再读；品牌/机型名不引述（视觉模型会读错）
3. **隐式那层别漏**：抹掉画面上那行字 ≠ 抹掉拍摄时间——EXIF/XMP 里的时间戳两版都在，报一句
4. **不擅自改图**：只说结论；要不要剥/修由用户点

## 五、踩坑

- 这类脚本要 numpy/PIL/scipy：用 `/opt/data/.venv/bin/python` 跑，别用裸 `python3`
- 视觉模型答「这两张有什么不同」是**描述比对**不是差分：小字、位置、有无都会读错，只能用来复核已定位的那一块
- 差分只回答「哪一块不一样」；那块是不是水印，还要**裁开放大看画面** + **翻文件层看声明**（有没有水印层/增益图层，配方 → `video-analysis/references/motion-photo.md`）

## 六、答「差距在哪」：画面层之外还有文件层

差分定位完那行字只算一半。用户要「看看差距」，就得把两份存档逐段拆开对齐（手机相册水印三层结构 → `video-analysis/references/motion-photo.md` §八）：

| 层 | 水印版 | 无水印版 |
|---|---|---|
| 画面 | 那行字烧在主图像素里 | 干净（纹理与邻域一致 = 真没画上去，不是涂抹） |
| 附带段 | 2×96×2304 子图（字节相同的重复）+ 524×74 RGBA PNG 水印层 | 无 |
| 声明 | XMP `MiCamera:XMPMeta`（offset/length/尺寸/边距俱全） | 无 |
| 主图体积 | 反而更小（2.10MB vs 3.59MB，容器也不同：平铺 JPEG vs MPO） | 更大 |

三条口径：

1. **体积差 ≠ 画质差**——两版是两条保存管线，不是一张压过一张。
2. **水印是三层，剥层剥不掉那行字**：像素层还在；只有拿到无水印原件才算干净。
3. **α 反解只能救急**：用存下来的水印层反解，误差 172 → 61，看得出底下是什么但不干净（尺度对不上 + JPEG + 亮底削顶）。

### 心法 3 子项 · 截图找原件 · 池↔库对应 · 孪生判同 · 锁文件md5 · 情绪看提示词

   - **别人甩来的「截图」一律不是原图**：看图/相册界面截图**已被缩放又带着 UI 壳**，拿它识图、配图、归档都会失真（原件常 1536×2730 这种竖构图，截图可能是 887×1920）。**先把原件找回来再动手**，四步：① 读截图标题栏的**年月日＋时刻**；② 按这个时间戳去素材库里命中**以时间戳命名**的生成件（生图工具导出常用 **13 位毫秒**.png）；③ 用**像素尺寸／文件大小**回索引库的 `<NNN>-成品.png` 锁条目（那目录往往同时存着**当时的提示词原文**，是场景说明的一手来源）；④ 仍不放心再上 dhash 扫库。**整条判据链以「同一份文件的硬字段」收口，不以画面描述收口。**
   - ⚠️ **聊天缓存名里的 md5 前缀认不出原件**：收图后常缓存成 `img_<md5 前几位>.jpg`，那串是**转码后**字节的 md5，拿它对原件库**必然 0 命中**（尺寸、画面都对得上也照样不中）——别据此判「原件不在库里」，改回时间戳＋尺寸两条线继续找。
   - ✅ **但「素材池 ↔ 生图库」之间是同一份文件，md5 直接命中**：素材池里的导出件（`<毫秒>.png`）与归档库条目目录里的成品图（`<日期>_<NNN>_<名>/<NNN>-成品.png`）是**字节相同**的两份拷贝（实测 `1766202737337.png` ＝ `052-成品.png` ＝ `76da59ca…`）——定位条目**一步到位**。dhash／尺寸那条路留给「经过转发的图」。
     - **筛候选只要分钟级**：按截图界面上显示的那一刻，按那一分钟列池文件通常只剩 1–2 张，逐个 `md5sum` 对上即定案（实测 `1766051729990.png`（17:55:29）→ `022`；`1766079348549.png`（次日 01:35:48）→ `028`）。
     - **定案后立刻把「池文件 → 条目 → 去向（哪一篇）」写进台账**：条目名只是归档标签，这层对应关系是下次挑图查重的实据——不落账就得重推一遍。
   - 🆔 **同一场景常有孪生张，判同要算误差**（陷阱 20）：`scripts/twin-compare.py <目标> <候选…> --regions …`，同一张 ≈20、同族另一张 ≈40+。
   - 🧭 **内容区裁不准时改算「相关」，不要先切 UI**：逐行方差找截图边界会把暗部行误判进 UI。做法是降采样到宽 ~160，对每个候选按 `0.85–1.0` 倍宽逐档缩放，在**整张截图里逐位置滑动**取归一化相关系数最大值（滑动自带对齐，不必先裁准）。判据同样是**差距**：命中 ~0.87、同族另一张 ~0.27 才敢锁；平均绝对差一起报（重编码会让同一张也落到 10 上下，别拿 0 当标准）。反推出的内容区应当就是 `9:16`（实测 `y=172–1749`、`887×1577`），比例对不上说明匹配错了。手写滑动循环比 `cv2.matchTemplate` 稳——后者跨大版本对参数顺序与尺寸断言的要求会变。
   - 🔒 **锁到「文件＋md5」，别锁在编号上**：一个编号下可能是同一提示词的多张输出（`041` vs `041A`），画面差异可以很大——落档要写清是哪一张成品并记 md5。
   - 🎭 **画面情绪看提示词原文，不看旧剧情块的解读**：同一条目里旧故事块对画面的解读是**用途叙事**，不是画面事实（实测：旧块记「眼神急切坚定／救援向」，而提示词原文写的是「面部带笑意且脸颊泛红」）。写情绪／场景口径前先读那目录里的提示词原文。
